## User Scenarios & Testing *(mandatory)*

> 平台"多门店"定位的线下载体交付：游客能找到附近/指定区县的营业门店并查看详情，
> 运营能管理门店档案与营业状态。全部行为基于既有契约：store 表（000031：编码全局唯一、
> GB/T 2260 区划码、GCJ-02 经纬度、自提开关、营业/歇业/软删三态）、service 接口
> `IStoreLogic`（internal/service/shop/misc.go）、权限码 `store:manage:create/update/delete`（000032 种子）。
> 规格只验收行为；自提/核销的交易侧消费（结算自提候选、核销核减）归交易批次（012+）。

### User Story 1 - 游客门店检索（Priority: P1）🎯 MVP

游客（无需登录）按区县筛选门店列表，或按经纬度做附近检索（半径内、按距离由近到远、返回距离米数）；两种方式都只出现营业中的门店；可查看单店详情（完整地址、营业时间、电话、自提标识、营业状态）。

**Why this priority**: 门店对 C 端的价值就在"找到店"；自提下单（后续批次）依赖本故事的数据可见性。

**Independent Test**: 造 3 家门店（2 营业 1 歇业，不同区县与坐标）→ 区县筛选只出该区县营业店 → 附近检索按距离升序且歇业店不出现 → 详情返回完整档案。

**Acceptance Scenarios**:

1. **Given** A 区营业店、B 区营业店、A 区歇业店，**When** 按 A 区区划码检索，**Then** 仅返回 A 区营业店。
2. **Given** 三家营业店距检索点 500m/3km/30km，**When** 以检索点按默认半径附近检索，**Then** 500m 与 3km 的门店按距离升序返回且带 distanceM，30km 的不出现（超默认半径）。
3. **Given** 检索半径扩大到覆盖 30km 门店，**When** 附近检索，**Then** 三家按距离升序全部返回。
4. **Given** 一家门店未录入经纬度，**When** 附近检索，**Then** 该店不出现（无法计算距离，不伪装距离 0）。
5. **Given** 区县与经纬度同时传入，**When** 检索，**Then** 按附近检索执行（经纬度优先，二选一语义的既定取向）。
6. **Given** 任一门店 ID（含歇业店），**When** 查看详情，**Then** 返回完整档案并携带营业状态与自提标识；不存在的门店返回资源不存在错误。

### User Story 2 - 后台门店管理（Priority: P1）

授权运营创建门店（名称、省/市/区县区划码、详细地址、可选经纬度/营业时间/电话/自提开关——门店编码由系统生成且全局唯一）、修改档案（含营业/歇业切换与自提开关）、软删除、按状态与关键词（名称/编码）分页检索、查看详情（含编码与坐标）。

**Why this priority**: 没有门店档案就没有游客检索；管理面是数据源头。

**Independent Test**: 创建门店（返回系统生成的编码）→ 列表可见 → 歇业后游客列表不出现 → 软删后后台列表亦不可见。

**Acceptance Scenarios**:

1. **Given** 授权运营，**When** 创建门店（未传编码），**Then** 成功且返回系统生成的全局唯一门店编码；两次创建得到不同编码。
2. **Given** 创建时省/市/区县任一区划码缺失或非 6 位数字，**When** 提交，**Then** 拒绝并给出可读错误。
3. **Given** 营业中门店，**When** 置为歇业，**Then** 游客列表不再出现（游客详情仍可见但状态为歇业、自提不可用语义）。
4. **Given** 关键词命中名称或门店编码，**When** 后台列表检索，**Then** 仅返回匹配行且分页正确；状态筛选同理。
5. **Given** 软删门店，**When** 后台列表/详情与游客列表/详情访问，**Then** 均不再出现（资源不存在）。

### User Story 3 - 权限挂接与状态语义（Priority: P2）

门店写操作（新增/修改/删除）按权限点校验：持权角色放行、无权拒绝、超管直通；查询类端点仅要求登录；歇业态的语义在数据上自洽——门店可见但"不可自提/核销"由状态与自提开关共同承载，供交易批次消费。

**Why this priority**: 延续批次 01 的 RBAC 机制；无权限校验则门店档案可被任意登录管理员改动。

**Independent Test**: 无权账号调"新增门店"被拒；超管放行；持 `store:manage:update` 的账号可改但删除仍被拒。

**Acceptance Scenarios**:

1. **Given** 不持 `store:manage:create` 的账号 A 与超管，**When** 各自调"新增门店"，**Then** A 被拒（权限不足）、超管成功。
2. **Given** 持 `store:manage:update` 但不持 `store:manage:delete` 的账号 B，**When** 修改门店与删除门店，**Then** 修改成功、删除被拒。
3. **Given** 歇业门店（自提开关开），**When** 游客查看，**Then** 自提标识如实返回，但状态标明歇业（"不可自提"的交易侧裁决由后续批次执行）。

### Edge Cases

- 门店编码生成冲突（极小概率）：系统重试生成，调用方无感知。
- `radiusKm` 域外值：负数/零回退默认 10，超上限回退上限（100）。
- 附近检索命中 0 家：返回空列表而非错误（正常业务态）。
- 经纬度只传其一：视为未提供附近检索（回退区县筛选或默认列表），不计算残缺距离。
- 软删门店的编码：不复活、不释放复用（编码全局唯一含已删行）。
- 本批不校验"门店被进行中自提订单引用"——核销批次（012+）落地时补引用校验（届时删除需过引用关）。

## Requirements *(mandatory)*

### Functional Requirements

**游客侧（common）**

- **FR-001**: 系统 MUST 提供游客门店列表：仅返回营业中（status=1）且未软删的门店。
- **FR-002**: 列表 MUST 支持按区县区划码筛选。
- **FR-003**: 列表 MUST 支持按经纬度附近检索：仅返回半径内门店，按距离升序，每行携带距离（米）。
- **FR-004**: 未录入经纬度的门店 MUST NOT 出现在附近检索结果中。
- **FR-005**: 区县与经纬度同时提供时 MUST 按附近检索执行（经纬度优先）。
- **FR-006**: 系统 MUST 提供游客门店详情：完整档案 + 营业状态 + 自提标识；歇业店可见；不存在的门店返回资源不存在错误。

**后台侧（admin）**

- **FR-007**: 系统 MUST 提供门店创建：名称与三级区划码、详细地址必填；门店编码由系统生成且全局唯一（调用方不传）。
- **FR-008**: 区划码 MUST 校验为 6 位数字；经纬度可缺省（缺省门店不参与附近检索）。
- **FR-009**: 系统 MUST 提供门店修改：档案字段与营业/歇业状态、自提开关；目标不存在时返回资源不存在错误。
- **FR-010**: 系统 MUST 提供门店软删除：删除后对后台与游客均不可见。
- **FR-011**: 系统 MUST 提供后台门店列表：状态筛选 + 名称/编码关键词模糊 + 分页。
- **FR-012**: 系统 MUST 提供后台门店详情：含门店编码与坐标（游客详情不返回区划全栈与电话以外无差异……以契约字段为准）。

**权限与语义**

- **FR-013**: 新增/修改/删除 MUST 按权限点校验（`store:manage:create/update/delete`）：持权放行、无权拒绝（权限不足错误码）、超管直通；查询仅要求登录。
- **FR-014**: 歇业语义 MUST 以数据自洽承载：状态字段 + 自提开关如实返回；"不可自提/核销"的交易侧裁决归后续批次。

### Key Entities *(include if feature involves data)*

- **门店（store）**：编码（全局唯一，系统生成）、名称、省/市/区县区划码（GB/T 2260 六位）、详细地址、经纬度（GCJ-02，可空）、营业时间、电话、自提开关、排序、状态（1 营业 2 歇业）、软删标记。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 本批 7 个端点全部可调用，`make check-stub` 中 admin 渠道桩数由 109 降至 104、common 渠道由 3 降至 1。
- **SC-002**: 附近检索行为可验证：距离升序、半径过滤、歇业/无坐标门店不出现（行为级测试）。

## Assumptions

- 门店编码由服务端生成（项目分布式 ID 约定场景），创建入参不含编码。
- 附近检索的距离计算采用球面距离公式（实现选型归 plan），检索在库内数据规模（数百店）下无性能专项。
- `radiusKm` 默认 10、上限 100；域外值静默回退（不报错）。
- 游客列表仅营业（接口契约口径）；表注释"歇业=展示但不可自提/核销"由详情可见性 + 交易侧裁决共同承接。
- `IStoreLogic` 缺 AdminDetail 方法——按批次 01 D6 模式微扩接口（复用 StoreItem 返回）。
- 本批零表结构变更、零新迁移、零新 DTO（StoreQuery/StoreItem/StoreInput 已就位）。
- 批次 DoD：admin 109→104、common 3→1；全量测试绿；本批文件 lint 零问题。
- 门店修改采用**全量覆盖语义**（后台表单提交完整档案, 空值即清空）：显式字段白名单保证零值可写
  （关闭自提/置歇业），消除 bool 字段"未传 vs 传 false"二义（research D6 实现期决策）。
