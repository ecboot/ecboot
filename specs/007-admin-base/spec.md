## User Scenarios & Testing *(mandatory)*

> 平台治理域的首个交付批次：后台管理员从"无法登录"到"可管账号/角色/配置"。
> 全部行为基于既有契约：RBAC 五表（V10 迁移 + 000032 权限种子）、系统配置覆盖层语义（V30）、
> 双凭证会话基座（认证纵切片已交付）、service 接口 `internal/service/system/{rbac,ops}.go`。
> 规格只验收行为；本批范围外的端点（审计日志/看板/风控）归后续批次。

### User Story 1 - 后台登录与会话（Priority: P1）🎯 MVP

管理员以用户名 + 密码登录（携带图形验证码时强校验），成功返回访问凭证、刷新凭证、姓名与是否超管标记；登录成功与失败均留审计；支持登出（双凭证同毁）、刷新凭证（换发新对、旧对失效）、查看个人信息（用户名/姓名/角色编码列表）、修改密码（校验原密码，改后旧密码失效）。

**Why this priority**: 后台一切操作的前置；没有登录，账号/角色/配置管理全部不可达。

**Independent Test**: 种子超管登录 → 调个人信息 → 修改密码 → 旧密码重登被拒 → 登出后原凭证失效，全程无需其他故事交付。

**Acceptance Scenarios**:

1. **Given** 种子超管账号，**When** 以正确用户名密码登录，**Then** 返回双凭证、真实姓名与 isSuper=true，且登录审计记录一条成功。
2. **Given** 正确用户名 + 错误密码，**When** 登录，**Then** 拒绝并返回统一错误码，审计记录一条失败（含 IP/UA）。
3. **Given** 请求携带了 captchaKey + captchaCode，**When** 登录，**Then** 先校验图形验证码，错误则拒绝且不留会话。
4. **Given** 有效会话，**When** 登出（携带 refreshToken），**Then** 访问凭证与刷新凭证同时失效，再访受保护端点被拒。
5. **Given** 有效 refreshToken，**When** 刷新，**Then** 返回新凭证对，旧 refreshToken 再用被拒。
6. **Given** 已登录管理员，**When** 查询个人信息，**Then** 返回用户名、姓名与其角色编码列表。
7. **Given** 已登录管理员，**When** 以正确旧密码修改为新密码，**Then** 修改成功且旧密码登录被拒、新密码登录成功。

### User Story 2 - 后台账号管理（Priority: P1）

授权管理员创建后台账号（用户名唯一、初始密码）、修改姓名与状态（启用/禁用）、软删除、为账号分配角色（全量替换）、按状态与关键词（用户名/姓名模糊）分页查询列表、查看账号详情（含角色编码与最后登录时间）。

**Why this priority**: 平台运营的第一治理动作——先有人（账号）再有权（角色）。

**Independent Test**: 创建账号 → 分配角色 → 列表可见 → 禁用后该账号无法登录 → 软删后列表不可见。

**Acceptance Scenarios**:

1. **Given** 授权管理员，**When** 以未占用用户名创建账号，**Then** 成功返回账号 ID；新账号可用初始密码登录。
2. **Given** 已存在同名账号，**When** 再以该用户名创建，**Then** 拒绝（用户名唯一）。
3. **Given** 启用中的账号，**When** 置为禁用，**Then** 该账号后续登录被拒，已有会话失效或不可再用。
4. **Given** 账号已分配角色 A，**When** 全量替换为角色 B，**Then** 详情中角色编码仅剩 B（重复执行结果一致，幂等）。
5. **Given** 列表页请求（status=2 或 keyword 命中），**When** 查询，**Then** 仅返回匹配行且分页总数正确。
6. **Given** 被软删的账号，**When** 查询列表与详情，**Then** 不再出现；尝试登录被拒。

---

### User Story 3 - 角色与权限管理（Priority: P2）

授权管理员维护角色（增/改/软删/列表/详情）、查看权限树（菜单/按钮/接口统一树，与权限种子同源）、为角色全量替换权限集合；权限校验生效：受权限点保护的端点仅对持权角色（或超管）开放。

**Why this priority**: 有了账号之后才需要分权；权限拦截让 RBAC 从"数据管理"变为"真实访问控制"。

**Independent Test**: 建角色 → 分配部分权限 → 挂到新账号 → 该账号持权端点可调、无权端点被拒 → 超管全部可调。

**Acceptance Scenarios**:

1. **Given** 无重名编码，**When** 创建角色，**Then** 成功；编码重复时拒绝。
2. **Given** 已被账号引用的角色，**When** 删除，**Then** 拒绝并提示存在引用（无引用的角色可软删）。
3. **Given** 权限树查询，**When** 返回，**Then** 树结构含菜单/按钮/接口三类节点，层级与权限种子一致，子节点嵌套于父节点 children。
4. **Given** 角色已分配权限集 A，**When** 全量替换为权限集 B，**Then** 角色详情仅返回 B（重复执行结果一致）。
5. **Given** 持 `system:role:manage` 的账号 A 与不持该权限的账号 B，**When** 各自调用"新增角色"，**Then** A 成功、B 被拒（权限不足错误码）。
6. **Given** isSuper=true 的账号，**When** 调用任意受保护端点，**Then** 跳过权限点校验直接放行。

### User Story 4 - 系统配置（Priority: P2）

授权管理员查询系统配置列表（编码/名称/值/类型/说明含代码默认值/启停状态）与修改配置（值、启停）；停用或缺失的配置在业务读取时回退代码默认值，不阻断业务；修改在缓存窗口内生效。

**Why this priority**: 配置是运营调参入口，依赖面小；语义（覆盖层 + 兜底）在 V30 已定，本批交付管理面。

**Independent Test**: 改某配置值 → 列表反映新值 → 停用该配置 → 业务侧读取回退默认值。

**Acceptance Scenarios**:

1. **Given** 存在种子配置，**When** 查询列表，**Then** 返回全部配置项，含说明与代码默认值信息。
2. **Given** 某配置，**When** 修改其值并启用，**Then** 列表返回新值；业务读取按新值生效（缓存窗口内允许延迟）。
3. **Given** 某配置被停用，**When** 业务读取该配置，**Then** 回退代码默认值，业务不报错。
4. **Given** 修改请求携带非法类型值（如整数型配置传非数字），**When** 提交，**Then** 拒绝并给出可读错误。

### User Story 5 - 基础端点（Priority: P3）

common 渠道提供 ping 健康检查（无需认证，返回存活标识）；提供 mock_latest_sms 调试桩（返回最近一条模拟短信验证码，仅限非生产环境，生产环境拒绝）。

**Why this priority**: 开发联调与部署探活的基础设施，与业务无关但属本批端点清零范围。

**Independent Test**: 无凭证调 ping 返回成功；非生产环境调 mock_latest_sms 返回最近模拟验证码。

**Acceptance Scenarios**:

1. **Given** 服务运行中，**When** 调用 ping（无认证），**Then** 返回成功响应。
2. **Given** 非生产环境，**When** 调用 mock_latest_sms，**Then** 返回最近一条模拟短信内容/验证码。
3. **Given** 生产环境配置，**When** 调用 mock_latest_sms，**Then** 拒绝且不泄露任何短信内容。

### Edge Cases

- 并发多次登录失败：本批只留审计不锁定账号（表结构无锁定字段，锁定机制属风控域后续批次）。
- 删除/禁用自己、删除超管账号：禁止（自我锁死与超管保护）。
- 角色/账号软删后，其历史关联（账号-角色、角色-权限）如何处理：关联不复活已删实体，详情查询不返回已删侧名称之外的内容。
- 配置修改的并发提交：后写覆盖后写可见，无合并语义（覆盖层定位）。
- 刷新凭证被重放（已用过的 refreshToken 再次使用）：拒绝并要求重新登录。
- 无权限账号访问未标注权限点的端点：仅要求登录，不做权限点校验。

## Requirements *(mandatory)*

### Functional Requirements

**登录与会话**

- **FR-001**: 系统 MUST 提供后台登录：校验用户名 + 密码，成功返回访问凭证、刷新凭证、姓名、超管标记。
- **FR-002**: 系统 MUST 在登录成功与失败时各写一条登录审计（含 IP、User-Agent、成功与否）。
- **FR-003**: 系统 MUST 在请求携带图形验证码时先校验验证码，不通过即拒绝登录。
- **FR-004**: 系统 MUST 提供登出：访问凭证与刷新凭证同时失效。
- **FR-005**: 系统 MUST 提供凭证刷新：有效 refreshToken 换发新凭证对，旧 refreshToken 一次性作废。
- **FR-006**: 系统 MUST 提供个人信息查询：用户名、姓名、角色编码列表。
- **FR-007**: 系统 MUST 提供修改密码：校验原密码；密码 MUST 以不可逆方式安全存储，任何环节不得明文落库或日志输出。
- **FR-008**: 禁用或软删账号 MUST 无法登录；其既有会话 MUST 失效或不可再用。

**后台账号管理**

- **FR-009**: 系统 MUST 提供后台账号创建（用户名唯一、初始密码）、修改（姓名/状态）、软删除、详情查询。
- **FR-010**: 系统 MUST 提供账号列表：支持状态筛选、用户名/姓名关键词模糊、分页，返回角色编码与最后登录时间。
- **FR-011**: 系统 MUST 提供账号-角色分配：全量替换语义，重复提交结果一致。
- **FR-012**: 系统 MUST 禁止删除/禁用操作者自身，MUST 禁止删除超管账号。

**角色与权限**

- **FR-013**: 系统 MUST 提供角色创建（编码唯一）、修改、软删除、列表（分页）、详情（含已分配权限 ID 集合）。
- **FR-014**: 系统 MUST 在角色被账号引用时拒绝删除。
- **FR-015**: 系统 MUST 提供权限树查询：菜单/按钮/接口统一树，与权限种子数据同源同层级。
- **FR-016**: 系统 MUST 提供角色-权限分配：全量替换语义（同事务删旧插新）。
- **FR-017**: 系统 MUST 在受权限点保护的端点上执行权限校验：持权角色放行、无权拒绝（统一权限不足错误码）、超管直通；未标注权限点的端点仅要求登录。
- **FR-018**: 权限校验 MUST 提供可供路由中间件调用的判定能力（按管理员 ID + 权限编码判定）。

**系统配置**

- **FR-019**: 系统 MUST 提供配置列表查询（编码/值/类型/名称/说明/启停状态）。
- **FR-020**: 系统 MUST 提供配置修改（值、启停状态）；值 MUST 按配置类型校验（整数/小数/字符串/布尔/JSON）。
- **FR-021**: 配置读取语义 MUST 保持覆盖层：停用或缺失回退代码默认值，不阻断业务。

**基础端点**

- **FR-022**: 系统 MUST 提供 ping 健康检查端点，无需认证。
- **FR-023**: 系统 MUST 提供 mock_latest_sms 调试端点：非生产环境返回最近一条模拟短信；生产环境 MUST 拒绝且不泄露内容。

### Key Entities *(include if feature involves data)*

- **后台账号（admin_user）**：登录名（唯一）、密码（不可逆存储）、姓名、超管标记、状态、软删标记、最后登录时间。
- **角色（admin_role）**：名称、编码（唯一）、描述、状态、软删标记；与账号多对多（admin_user_role），与权限多对多（admin_role_permission）。
- **权限（admin_permission）**：名称、编码（模块:资源:动作）、类型（菜单/按钮/接口）、父子层级、排序、状态；种子数据见 000032 迁移。
- **系统配置（system_config）**：编码（唯一）、值、值类型、名称、说明（含代码默认值）、启停状态。
- **登录审计（admin_login_log）**：账号、IP、UA、成功与否、时间（只追加）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 本批 22 个端点全部可调用，`make check-stub` 中 admin 渠道桩数由 129 降至 107、common 渠道由 5 降至 3（本批清零 22）。
- **SC-002**: 一名新管理员从"被创建 → 登录 → 被授权 → 持权操作 → 被禁用后无法登录"的完整旅程测试通过。
- **SC-003**: 权限拦截行为可验证：无权角色访问受保护端点 100% 被拒，超管 100% 放行（行为级测试）。
- **SC-004**: `make test` 全绿（含既有认证/交易链路回归），`make lint` 通过。
- **SC-005**: 本批范围内 `CodeNotImplemented` 桩数为 0。

## Assumptions

- 会话机制复用已交付的双凭证会话库（与 user 渠道同源），管理员会话时长独立可配，默认与现有一致（7 天），后续可收紧。
- 登录图形验证码为"携带即强校验"；是否强制携带由后续风控/配置决定，本批不强制。
- 登录失败仅审计留痕，不做账号锁定（无表结构支撑，属风控域后续演进）。
- 个人信息查询需在 `IAdminAuthLogic` 上扩展一个查询方法（接口微扩，plan 阶段落签名）。
- 权限点与端点的映射在 plan 阶段确定机制（映射表或注解解析），种子权限编码为准绳。
- mock_latest_sms 的环境判定依据运行环境配置（生产为 prod 时拒绝）。
- 本批不迁移 000010/000032 之外的表结构；无新增迁移。
