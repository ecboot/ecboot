## User Scenarios & Testing *(mandatory)*

> 纵切片（walking skeleton）：从基础对象到登录可用的一条完整链路。此后所有业务特性都生长在这条骨架上。

### User Story 1 - 统一 Web 基座（Priority: P1）

小程序前端开发者（API 消费方）与后端开发者约定：所有接口返回统一结构（状态码/消息/数据），业务错误、参数校验错误、未知错误都映射为友好且可编程判定的响应——前端一套拦截器处理全部接口，无需逐接口适配。

**Why this priority**: 一切端点的地基；后写任何接口都会固化响应形态，必须最先定型。

**Independent Test**: 一个探测端点分别触发"业务异常/参数校验失败/未知异常"，三种场景返回同一结构、不同错误码。

**Acceptance Scenarios**:

1. **Given** 任意接口抛出业务异常（携带错误码），**When** 调用，**Then** 响应为统一结构，code=业务错误码、message=用户可读文案、data 为空；响应不含堆栈信息。
2. **Given** 请求参数不满足校验规则，**When** 调用，**Then** 响应 code=统一参数错误码，message 标明具体字段与原因。
3. **Given** 接口发生未预期错误，**When** 调用，**Then** 响应 code=统一系统错误码并附追踪号（可用于日志排查），不泄漏内部细节。

---

### User Story 2 - 图形验证码（Priority: P1）

用户在发送短信验证码前，先获取图形验证码并输入通过校验，防止短信被脚本滥用。

**Why this priority**: 短信验证码的防刷前置；验证码组件是 infra-core 的第一个技术组件，验证组件容器形态。

**Independent Test**: 获取一张验证码图片 → 用正确答案校验通过、错误答案被拒且同一凭证不可复用。

**Acceptance Scenarios**:

1. **Given** 用户请求图形验证码，**When** 获取成功，**Then** 返回图片与一次性凭证；凭证在有效期内可校验一次。
2. **Given** 同一凭证已校验过（无论成败），**When** 再次使用，**Then** 校验失败（一次性）。
3. **Given** 凭证超过有效期，**When** 校验，**Then** 失败并提示重新获取。

---

### User Story 3 - 手机号注册登录（Priority: P1）🎯 MVP

用户输入手机号 + 短信验证码即可完成"注册即登录"（账号不存在自动创建）；登录成功发放会话凭证；每次登录留痕；久未登录的账号在下一次登录时按休眠分级要求更强核身。

**Why this priority**: 核心链路 MVP——US1/US2 完成后即可闭环交付"用户能进门"。

**Independent Test**: 新手机号走完"图形码→短信码→登录"三步，返回凭证；用凭证可访问受保护端点；登录日志与最后登录时间落库。

**Acceptance Scenarios**:

1. **Given** 全新手机号与正确短信验证码，**When** 提交登录，**Then** 自动注册并登录成功，返回会话凭证；库内手机号以密文+哈希存储（无明文）。
2. **Given** 已注册手机号与正确验证码，**When** 登录，**Then** 成功并返回凭证，登录日志记录成功、`last_login_at/last_active_at` 更新。
3. **Given** 验证码错误或过期，**When** 登录，**Then** 拒绝且提示重试；连续失败达到上限后该手机号被临时锁定。
4. **Given** 账号距上次活跃 ≥90 天（阈值可配置），**When** 登录，**Then** 额外要求更强的身份核验（本切片实现为：强制重新完成全套验证码核验）。
5. **Given** 被禁用账号，**When** 登录，**Then** 拒绝并告知原因。
6. **Given** 两个请求并发以同一手机号首次注册，**When** 同时提交，**Then** 恰好一个成功（哈希唯一约束兜底），另一个按已注册流程登录成功。

---

### User Story 4 - 会话凭证生命周期（Priority: P1）

登录用户携带凭证访问受保护接口；凭证可校验、可过期、登出即失效。

**Why this priority**: 与 US3 同属 MVP——没有凭证校验，"登录"没有消费方。

**Independent Test**: 登录获得凭证 → 携带访问受保护端点成功 → 登出后同凭证访问被拒。

**Acceptance Scenarios**:

1. **Given** 有效凭证，**When** 访问受保护端点，**Then** 请求通过且接口能识别当前用户身份。
2. **Given** 已登出或已过期的凭证，**When** 访问受保护端点，**Then** 拒绝并返回统一的未登录错误码。
3. **Given** 凭证临近过期，**When** 活跃使用，**Then** 可获得续期（滑动过期）。

---

### User Story 5 - 微信登录（开发态 mock）（Priority: P2）

用户以微信授权身份登录：取得微信侧身份标识（开发态以 mock 服务模拟），若该身份未绑定且能取得手机号，按**手机号优先归并**规则——手机号已有账号则把微信身份绑上去并登录，否则新建账号。

**Why this priority**: 双通道之一；mock 形态先打通归并规则，真实微信接入另立特性。

**Independent Test**: mock 微信身份 A 携带已注册手机号登录 → 登录到既有账号且该账号此后可用微信身份直接登录（openid 已绑定）。

**Acceptance Scenarios**:

1. **Given** mock 微信身份 + 已注册手机号，**When** 登录，**Then** 登录既有账号（非新建），微信标识绑定到该账号。
2. **Given** 微信身份已绑定某账号，**When** 直接以微信身份登录，**Then** 成功且无需再验证手机号。
3. **Given** 微信身份欲绑定的账号已绑定了另一个微信身份，**When** 登录，**Then** 拒绝并引导走人工渠道（不做自动换绑）。

### Edge Cases

- 图形验证码与短信验证码各自独立有效期（默认 5 分钟）、独立频控；短信默认 60 秒重发间隔。
- 同一手机号验证码连续错误达到上限（默认 5 次）→ 锁定 30 分钟（阈值可配置）。
- 验证码校验成功但登录环节失败：验证码仍按已消费处理（一次性不可回滚）。
- 手机号格式校验在入口拦截（不进入发码流程）。
- 休眠分级读取的是 `last_active_at`（非登录态）；阈值经系统配置可调。
- mock 微信身份标识的碰撞（两个用户同 mock openid）按重复绑定处理拒绝。
- 会话凭证登出后的并发请求（登出瞬间在途请求）以登出时刻校验为准，允许微小竞态但绝不放行已失效凭证的新请求。
- 注册即登录时 `register_channel` 按实际渠道记录（1小程序 2H5）。

## Requirements *(mandatory)*

### Functional Requirements

**统一 Web 基座**

- **FR-001**: 全部对外接口 MUST 返回统一响应结构（状态码/消息/数据三段式），成功与失败形态一致。
- **FR-002**: 系统 MUST 提供分域错误码体系与统一错误码出口；业务异常携带错误码后由全局处理映射为统一响应。
- **FR-003**: 参数校验失败 MUST 返回统一参数错误码并标明字段与原因；未预期错误 MUST 返回统一系统错误码 + 追踪号，且 MUST NOT 泄漏堆栈与内部信息。
- **FR-004**: 服务端 MUST 为每次请求生成贯穿日志的追踪号并回传响应头。

**图形验证码**

- **FR-005**: 系统 MUST 提供图形验证码获取与一次性校验（默认有效期 5 分钟，可配置）；校验后凭证立即失效。
- **FR-006**: 图形验证码的生成/存储/校验 MUST 实现为可复用的技术组件（不与任何渠道耦合），验证码凭证 MUST 有服务端存储（不信任客户端）。

**短信验证码（mock 发送）**

- **FR-007**: 通过图形验证码校验后方可请求短信验证码；短信验证码为 6 位数字、默认 5 分钟有效、一次性消费。
- **FR-008**: 短信发送在开发态 MUST 以 mock 方式落地（记录日志/控制台），发送接口 MUST 抽象为组件（真实渠道接入时零改动调用方）。
- **FR-009**: 发码 MUST 有频控：同一手机号 60 秒内不可重发；连续校验失败 5 次锁定 30 分钟（阈值可配置）。

**注册登录与归并**

- **FR-010**: 手机号+短信验证码 MUST 支持"注册即登录"：账号不存在自动创建，存在直接登录；手机号 MUST 以密文存储并以加盐哈希做唯一性/检索（库内无明文，复用既有表结构）。
- **FR-011**: 微信身份登录 MUST 实现**手机号优先归并**：能取得手机号且已有账号 → 绑定微信身份到既有账号并登录；未命中 → 新建账号；既有账号已绑定其他微信身份 → 拒绝并引导人工渠道。
- **FR-012**: 每次登录（成功/失败）MUST 写登录日志（渠道/结果/IP/UA）；成功登录 MUST 更新 `last_login_at` 与 `last_active_at`。
- **FR-013**: 登录 MUST 执行休眠分级核身：距 `last_active_at` ≥90 天强制完整验证码核验（阈值可配置，经系统配置）；禁用账号 MUST 拒绝登录。
- **FR-014**: 注册/登录入口 MUST 先做手机号格式校验，非法格式不进入发码流程。

**会话凭证**

- **FR-015**: 登录成功 MUST 发放会话凭证（不透明令牌，服务端存会话）；受保护端点 MUST 依据凭证识别用户身份。
- **FR-016**: 凭证 MUST 支持登出即失效与过期失效；未登录访问受保护端点 MUST 返回统一未登录错误码。
- **FR-017**: 凭证 MUST 支持滑动续期（活跃使用时延长有效期）。
- **FR-018**: 公共端点（验证码获取/校验、登录、健康探针）MUST 无需凭证即可访问，白名单集中配置。

### Key Entities *(include if feature involves data)*

- **统一响应（Unified Response）**: 三段式结构（状态码/消息/数据），全系统唯一响应形态。
- **错误码（Error Code）**: 分域编号的业务/系统错误标识，是前后端的错误契约。
- **验证码凭证（Captcha Ticket）**: 一次性服务端凭证（图形/短信两类），含有效期与消费语义。
- **会话凭证（Session Token）**: 登录态的不透明令牌，服务端管理生命周期（创建/续期/失效）。
- **用户（User）**: 既有实体（密文手机号+哈希、微信标识、休眠时间戳、登录日志）——本切片只新增读写行为，不改结构。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户从打开登录页到登录成功 ≤3 次交互（图形码→短信码→登录）、30 秒内完成。
- **SC-002**: 切片内全部端点（含三类错误注入场景）响应结构 100% 符合统一契约，零例外。
- **SC-003**: 验证码防刷规则全部可验证生效：一次性消费、有效期过期、60 秒频控、5 次锁定——每条有正反用例。
- **SC-004**: 微信归并场景验证：已有手机号账号经微信身份登录后为同一账号（以手机号哈希与账号 ID 双重验证），不产生重复账号。
- **SC-005**: 登录结果可审计：每次登录尝试在登录日志中可查（渠道/结果/IP/时间），成功率可统计。
- **SC-006**: 休眠分级生效：≥90 天未活跃账号登录被要求强核身（阈值改配置后 30 分钟内生效，无需重启）。
- **SC-007**: 库内全程无明文手机号（结构断言 + 写入路径验证）。

## Assumptions

- 短信为开发态 mock（日志输出），短信组件抽象接口，真实渠道（阿里云/腾讯云）另立特性接入。
- 微信 `code2session`/`getPhoneNumber` 为开发态 mock（配置开关 + 固定测试身份），真实接入另立特性；mock 身份不影响归并规则的真实性。
- 会话凭证 V1 采用服务端会话（不透明令牌 + 服务端存储、滑动过期），JWT 为演进路径；具体存储介质与签名机制属实现细节。
- 手机号加密（密文+盐哈希）的算法选择属实现细节，规格只约束"库内无明文 + 哈希检索"结果。
- 验证码有效期/频控/锁定阈值全部走系统配置，默认值：图形 5 分钟、短信 5 分钟、重发 60 秒、锁定 5 次/30 分钟。
- 本切片不含：密码登录、账号注销流程、后台（RBAC）登录、真实短信/微信渠道、多端登录设备管理。
- 安全基线（接口白名单）仅覆盖本切片端点；后台渠道的安全配置随后台特性建设。
