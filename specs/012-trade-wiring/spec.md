### User Story 1 - 前置修复：积分抵扣生效（Priority: P1）🎯 MVP

结算试算的积分抵扣当前恒为 0（查询了不存在的列导致 SQL 报错被静默吞掉）。修复后：会员有积分余额且勾选使用时，试算按"1 积分=1 分、上限=可用积分与可抵金额较小者"计入抵扣。

**Why this priority**: 积分抵扣是优惠三构成之一；带 bug 进入交易闭环会污染金额账本与后续对账。

**Independent Test**: 造积分余额 500 的会员 → 试算（勾选积分）→ 抵扣额>0 且与余额/上限一致；未勾选则为 0。

**Acceptance Scenarios**:

1. **Given** 会员积分余额 500（=500 分），**When** 结算试算并勾选积分，**Then** 积分抵扣按 min(500, 可抵上限) 计入 AmountBook。
2. **Given** 会员积分余额 0 或未勾选，**When** 试算，**Then** 积分抵扣为 0。
3. **Given** 无积分账户行的会员，**When** 试算（勾选积分），**Then** 抵扣 0 且不报错（无行不是错误）。

### User Story 2 - 购物车连线（Priority: P1）

会员加购/改量/勾选/移除/结算试算五个端点接入既有实现（`CartLogicImpl`）。

**Independent Test**: 加购 2 个 SKU → 改量 → 结算试算返回金额账本（各分项与合计勾稽）→ 移除。

**Acceptance Scenarios**:

1. **Given** 会员与可售 SKU，**When** 依次调 5 个购物车端点，**Then** 全部正常返回（不再返回未实现响应）。
2. **Given** 购物车含失效商品，**When** 试算，**Then** 该行进入 errors 提示且不计入金额（既有行为不回退）。

---

### User Story 3 - 订单 C 端连线（Priority: P1）

会员创建订单（幂等 token）/列表/详情/取消/确认收货五个端点接入；其中**确认收货**为既有实现缺失、本批新写（待收货 → 已完成，触发佣金计提事件位）。

**Independent Test**: 下单（幂等）→ 详情可见 → 取消（释放库存/退券/解冻余额）→ 另单确认收货（状态已完成）。

**Acceptance Scenarios**:

1. **Given** 正确请求，**When** 同一 request_token 提交两次，**Then** 返回同一订单号且库存只锁一次（既有幂等语义不回退）。
2. **Given** 待收货订单，**When** 确认收货，**Then** 状态 → 已完成；非待收货状态调用 → 拒绝（状态不允许）。
3. **Given** 待付款订单，**When** 取消，**Then** 状态 90 且库存释放、券退回、余额解冻（既有语义不回退）。

---

### User Story 4 - 支付（Priority: P1，新写）

会员对待付款订单发起支付（返回 mock 渠道唤起参数）、查询支付状态；渠道回调驱动支付成功（幂等四层防线：条件更新/唯一约束/金额校验/原文留档；同事务推进支付单 20、订单 20、库存核销、余额消费完成）；退款回调驱动售后单状态推进。

**Why this priority**: 资金入口；回调幂等是资金安全的核心防线。

**Independent Test**: 发起支付 → mock 回调 → 订单待发货、库存核销、余额消费完成；重复回调不改变状态。

**Acceptance Scenarios**:

1. **Given** 待支付订单（含余额抵扣），**When** 支付成功回调，**Then** 现金入账 = 应付 − 余额抵扣，余额核销完成。
2. **Given** 同一回调重放，**When** 处理，**Then** 直接应答成功且订单状态不再变化（幂等）。
3. **Given** 回调金额与应付不符，**When** 处理，**Then** 拒绝并留档（pay_callback_log）。
4. **Given** 支付成功但订单已取消，**When** 回调，**Then** 不推进订单（防脏态）。
5. **Given** 退款回调（售后单存在），**When** 处理，**Then** 售后单状态推进（幂等）。

---

### User Story 5 - 后台订单管理（Priority: P1，新写）

运营按状态/关键词分页查询订单、查看订单详情（含金额账本/商品行/时间线）、发货（填物流公司与单号）、取消订单（释放库存与优惠）、备注（内部备注，买家不可见）。

**Independent Test**: 造已支付订单 → 后台列表可见 → 发货（写物流信息，状态待收货）→ 备注成功 → 另单后台取消（释放资源）。

**Acceptance Scenarios**:

1. **Given** 已支付订单，**When** 后台发货（物流公司编码+单号），**Then** 状态 → 待收货且物流信息落库。
2. **Given** 非待发货状态订单，**When** 发货，**Then** 拒绝（状态不允许）。
3. **Given** 待付款订单，**When** 后台取消，**Then** 状态 90 且库存/优惠释放（与 C 端取消同语义）。
4. **Given** 任意订单，**When** 写内部备注，**Then** 备注落库且不出现在 C 端详情。
5. **Given** 状态/关键词筛选，**When** 后台列表查询，**Then** 仅返回匹配行且分页正确。

---

### User Story 6 - 会员优惠券（Priority: P2，新写）

会员查看可领券模板、领取（防超发+限领同事务）、查看我的券（未使用/已使用/已过期/已退回，过期惰性判定）；内部能力：结算可用券匹配（门槛与金额比较、按抵扣降序）、核销（下单事务内绑定单号）、退回（订单取消）。

**Independent Test**: 领券 → 我的券可见 → 试算可用券匹配 → 下单核销 → 订单取消退回。

**Acceptance Scenarios**:

1. **Given** 有可领券模板（未领完/未超限领），**When** 会员领取，**Then** 成功且我的券新增 1 张未使用。
2. **Given** 已超个人限领，**When** 再领，**Then** 拒绝（券已领完/超限）。
3. **Given** 已过期未使用券，**When** 查我的券，**Then** 显示已过期（惰性判定，不依赖定时任务）。
4. **Given** 可用券与商品金额，**When** 结算匹配，**Then** 仅返回门槛满足的券且按抵扣降序。
5. **Given** 下单核销的券，**When** 订单取消，**Then** 券退回为可再用（过期时间不变）。

### Edge Cases

- 支付回调的原文留档必须落库（对账依据）；金额不符/状态不符均留档但拒绝。
- 后台发货的物流公司编码取 `logistics_company`（批次 03 已交付字典）；停用公司不得用于新发货。
- 后台取消与 C 端取消共用同一状态机语义（订单 90 + 资源释放）。
- 券的"已过期"为惰性判定（查询时按有效期比较），不改表。
- 积分抵扣修复后仍须保持"余额<=0 不抵扣"语义。
- 本批零表结构变更、零新迁移。

## Requirements *(mandatory)*

### Functional Requirements

**前置修复**

- **FR-001**: 积分抵扣查询 MUST 修正（移除对不存在列的引用）；余额>0 且勾选时按 min(余额, 可抵上限) 计入；无账户行/余额<=0 → 0 且不报错。

**购物车（5 端点，连线）**

- **FR-002**: 系统 MUST 提供加购（重复加购累加）、改量/勾选、移除、详情、结算试算五端点，行为与既有实现一致（金额账本勾稽、失效行提示）。

**订单 C 端（5 端点）**

- **FR-003**: 系统 MUST 提供下单（幂等）、列表、详情、取消、**确认收货**五端点。
- **FR-004**: 确认收货 MUST 仅在待收货状态可执行（否则状态不允许错），完成后订单为已完成。

**支付（4 端点，新写）**

- **FR-005**: 系统 MUST 提供发起支付（返回 mock 唤起参数；应付<=0 拒绝）、支付状态查询。
- **FR-006**: 支付回调 MUST 幂等（重复回调直接应答成功且不再推进）+ 同事务推进（支付单/订单/库存核销/余额消费完成）+ 原文留档。
- **FR-007**: 回调金额与应付不符 MUST 拒绝并留档；订单已取消等脏态 MUST 不推进。
- **FR-008**: 退款回调 MUST 幂等推进对应售后单状态。

**后台订单（5 端点，新写）**

- **FR-009**: 系统 MUST 提供后台订单列表（状态/关键词筛选+分页）与详情（含账本/商品行/时间线）。
- **FR-010**: 发货 MUST 校验状态（仅待发货）并落物流公司与单号；**停用物流公司 MUST 拒绝**。
- **FR-011**: 后台取消 MUST 与 C 端取消同语义（状态 90 + 库存/券/余额释放）。
- **FR-012**: 内部备注 MUST 可写且**不出现在 C 端详情**（买家不可见）。

**会员优惠券（3 端点，新写）**

- **FR-013**: 系统 MUST 提供可领模板列表（过滤领完/超限/停发）、领取（同事务防超发与限领）、我的券（四态 + 过期惰性判定）。
- **FR-014**: 内部能力 MUST 提供：结算可用券匹配（门槛 + 按抵扣降序）、核销（绑单号）、退回（订单取消，有效期不变）。

### Key Entities

- **订单（trade_order）**：状态机（10 待付款/20 待发货/30 待收货/40 已完成/90 已取消）、金额账本（优惠三构成）、物流信息、内部备注。
- **订单项/订单日志（trade_order_item/log）**：商品行（含分摊）与时间线（只追加）。
- **支付单（pay_order）**：支付号、渠道、金额、状态（10 待支付 / 20 成功 / 30 支付失败 / 90 已关闭，以 000007 列注释为准）、渠道单号。
- **回调留档（pay_callback_log）**：渠道、原文、处理结果（对账依据）。
- **优惠券模板/会员券（coupon/user_coupon）**：门槛、抵扣值、有效期、限领、状态（未使用/已使用/已过期/已退回）、绑定订单号。
