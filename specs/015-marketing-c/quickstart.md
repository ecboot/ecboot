## 二、端到端场景（服务层测试覆盖，按序即一轮完整演示）

场景脚本落 `internal/service/shop/marketing_impl_test.go` + `play_impl_test.go`（TDD 先红后绿），打真实库并自清。

1. **秒杀闭环（SC-002，含批次 07 欠账清偿）**
   造秒杀场次（SKU 秒杀价 5.00 / 原价 10.00 / 限量 10）+ `inventory` → 列表可见（含秒杀价/剩余/限购）
   → **下单 2 件**：断言订单项 `price=5.00`（秒杀价快照）、`original_price=10.00`、订单应付按秒杀价；活动 `sold_count=2`、`inventory.locked=2`
   → **支付回调**：断言订单推进、`inventory.total/locked` 各 −2（批次 07 的欠账：此前必因核销未命中回滚）
   → **另造一单并取消**：断言 `sold_count` 与 `locked` 双双回补；活动库存不足/场次 SKU 不符 → 40003 / 50002。
2. **砍价闭环（SC-003）**
   造场次商品（原价 100.00 / 底价 60.00 / 最多 5 刀）→ 发起 → 当前价 = 100 − 8 = 92.00、`cut_count=1`
   → 会员 B 帮砍 → 84.00；B 再砍 → 50004；发起者本人砍 → 50002
   → 连砍至底价 → 每刀均分、**末刀补齐到恰好 60.00**（不砍穿）、状态 = 2 到底价
   → 超时单（`expire_time` 置过去）→ 砍 → 50002；并发帮砍同一单 → 只成功一次（`uk_record_helper` + 1062 转 50004）；风控端口注入"拦截" → 10005。
3. **助力闭环（SC-004）**
   造助力活动（需 3 人 / 每人限发起 1 次 / 奖励类型 1 券）→ 发起 → 进度 0/3
   → 三位好友各助力 → 第三人后状态 = 2 已完成发奖 + `finish_time`，且**发奖意图端口恰好被调用 1 次**
   → 重复助力 → 50007；本人助力自己的 → 50002；发起超限 → 50006；并发助力达标 → 发奖意图仍只 1 次。
4. **列表与首页（SC-005）**
   五类活动各造"进行中 + 已结束"各一个 → 各列表只回进行中的、按结束时间升序
   → 首页一次返回轮播/楼层/五入口（各 ≤3 条）/券；**任一块为空 → 返回空数组不报错**（清掉全部活动后再请求）。
5. **端点可达性**
   与批次 08 同规格的 HTTP 探活：公开端点（游客可直接访问）+ 会员端点（合法凭证可达、无凭证 10003）。

## 三、回归与边界

- 批次 01~08 全部测试保持绿；**特别注意交易链路**（本批改了 `order_impl.go` 的秒杀分支与 `cancelBy`）。
- **不做的事**：不实现拼团的成团/解散/退款（批次 10/11）；不实现风控规则引擎与发奖的实际发放（端口留出口）；不新增迁移；不改支付/售后/评价域既有实现。
