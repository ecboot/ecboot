# 分销关系链两级封顶

社交电商的获客依赖分享裂变，最自然的数据模型是可递归的多级关系树（每个用户记录完整上级路径，佣金逐级上溯）。我们决定**放弃**这种表达：`user_relation` 仅存"直接上级"（`inviter_id`）单列，一人一条记录，**结构上无法表达第三层及以上关系**。

理由：中国《禁止传销条例》将三级及以上层级计酬划为传销（刑事红线，不是设计偏好）。两级封顶是合规硬约束，必须落在数据结构层面——仅靠应用层校验的"多级表+用两级"形态，任何一次代码缺陷或后台改数都会越线，而结构上不存在祖父列/路径列/层级列，越线在落库环节即不可能。命中优先级（商品级佣金规则 > 分类级默认）由应用层在两级范围内解析，与层级封顶正交。

## Considered Options

- 多级路径表（`path` 列存 `A/B/C` 形式的祖先链，查询任意祖先）——被拒：表达力正是风险本身，结构上放行了三级以上。
- 祖父列冗余（`inviter_id` + `grand_inviter_id` 两列）——被拒：与单列 + 自查上级等价但诱导继续加列；单列形态让"加一层"必须走 DDL 变更 + 本 ADR 重审，天然引入评审摩擦。

## Consequences

- 二级佣金（邀请人的邀请人）通过两次单列查询解析：C 的 inviter=B，B 的 inviter=A；不存在更快的路径查询，属有意为之。
- 若未来法务确认可扩展层级（如海外市场），修订本 ADR 并重新设计关系链表属宪章级变更，不允许静默加列。
